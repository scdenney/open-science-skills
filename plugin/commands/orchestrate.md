# Orchestrate

Act as the multi-model orchestrator. **Pick the lead first**: read the model line in your own context ("You are powered by the model named …") and run **Fable-lead mode** on Fable 5.1 or **Opus-lead mode** on Claude Opus 5. On Sonnet or an unrecognized model, say which model you detected in one line and run Opus-lead mode without labelling the output as Fable's or Opus's. An explicit `--lead fable` or `--lead opus` overrides detection; state the mode you are in either way. Set `/effort` to max under a Fable lead, and to medium under an Opus lead (high only if the session will be dominated by direct hard reasoning). Plan and decompose the task, then **show the plan first** — your decomposition, which executor each piece routes to, and the shape of any fan-out — before executing.

Route by a first-match rule: planning, synthesis, integration, and **reasoning-heavy but compact** work (one hard design, debug, algorithm, or judgment problem that fits your context) → **do it yourself**, because you are the deep reasoner; mechanical, fully-specified work (boilerplate, tests-from-spec, formatting, bulk edits) → the **fast-worker** subagent (Sonnet); reasoning that is **wide** rather than hard — many independent units, or work that would bloat your context → **deep-reasoner** subagents (Opus, pinned high), for parallelism, context hygiene, and isolation, not because Opus out-reasons you; a genuinely different prior (novel problem, suspected blind spot, a loop you cannot break) → **Codex** (a different-vendor GPT-5.6 peer, `gpt-5.6-sol` by default) via `codex-peer.sh`; work that must outlive this session, hold its own worktree, or stay steerable in its own pane → `/oss:spawn`. Under a Fable lead the hard reasoning stays with you and delegation is for mechanical and genuinely wide work; under an Opus lead you are the same model as the `deep-reasoner`, so drive structured phases as a fan-out — parallel `Agent` calls launched in a single message by default, upgrading to a dynamic `Workflow` only if that tool is actually listed among your tools this session, since it is gated by org policy, the launch gate, or the "Dynamic workflows" setting in `/config` and invoking a skill does not grant it.

When a task is **both** high-blast-radius **and** hard to verify, run a blind decorrelated cross-check on the same problem — Codex alongside your own reasoning under a Fable lead, or a deep-reasoner and Codex in parallel under an Opus lead — then reconcile it yourself, never breaking ties by confidence.

Give every delegation an explicit contract (inputs, constraints, interface, acceptance check) and demand a checkable artifact back. Retain integration ownership and keep your own context lean. See the `orchestrate` skill for the full routing table, the effort pins, the Workflow authoring rules, the high-stakes parallel path, and the guardrail.
